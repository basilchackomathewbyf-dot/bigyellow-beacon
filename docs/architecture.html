Beacon Edge Architecture

Crew phones and the Master's dashboard talk only to an edge server on the ship, so everything works without internet. The edge server runs Gemma 3n offline and syncs a small delta with Google Cloud whenever the VSAT link is up.

One near-miss, end to end

  1. Crew member speaks in Hindi and attaches a photo in the app. ship Wi-Fi → POST /crew/near-miss
  2. FastAPI runs the safety rails on the input first.
  3. Gemma 3n transcribes, reads the photo and returns NearMiss JSON. Invalid JSON gets one retry against the schema.
  4. The app shows the draft and any clarifying question. The crew member confirms.
  5. The record is saved in Postgres and appears on the Master's dashboard straight away.
  6. The record goes into the outbox. When VSAT is up, the sync worker sends it to shore. POST /ingest/delta
  7. Gemini and Firestore vector search match it against sister vessels and the accident corpus.
  8. A fleet alert and the enriched brief come back down on the next pull. GET /ingest/updates

What crosses the link

Ship → shore

  • Near-miss records (structured)
  • Check-in scores, date only
  • Consented escalations
  • Photos, on a good link only

Shore → ship

  • Fleet alerts and clusters
  • Gemini-enriched brief
  • Safety lexicon and prompt updates
  • Model updates, when bandwidth allows

Never leaves

  • Check-in transcripts (stay on the phone)
  • Crew names or crew IDs
  • Individual wellbeing data to the Master
